## System and dependency map

Browser -> Next session cookie/proxy -> Nest JWT + workspace guard -> API services
-> Prisma/PostgreSQL. API persists ScanJob and attempts BullMQ dispatch. Worker
recovery redispatches persisted jobs. Worker modules use scope -> crawl/discovery ->
passive/active scanners -> authorization differentials -> evidence -> finding ->
correlation -> Qwen -> report libraries. Report HTML is on a shared filesystem;
PostgreSQL stores paths and hashes. The browser polls scan progress.

Frontend routes: workspaces, targets/scope, scans and scan assets/endpoints/findings/
authorization/reports, identity setup, audit, provider settings. State uses server
fetches and local React forms; no global store. Integration points are private
Qwen-compatible HTTP providers and scanner adapters. No live ticketing/source-control
integration exists. Colab notebooks and dataset scripts are local research artifacts.

Deployment: one common multi-stage Node image, API/worker/web processes, Postgres,
Redis, shared report volume, optional GPU Compose profile, GitHub quality/CodeQL/
container/deployment workflows. API startup currently migrates and seeds, including
resetting the configured administrator's password. No tenant RLS, backup restoration
acceptance, object-store retention, or deployment egress enforcement is verified.

## First increment invariants and failure behavior

- Resource IDs never confer access; authenticated membership supplies tenant context.
- Organization/workspace/client/engagement references must agree in PostgreSQL.
- Existing scans remain readable; execution without an engagement grant fails closed.
- Grants bind a scope/ROE revision and document hash, have a time window, and can be
  revoked. Scope changes require new authorization; historical grants are retained.
- Lifecycle changes and audit events commit together; concurrent stale writes fail.
- Queue messages cannot supply risk, permission, or approval. Workers reconstruct
  policy from database state and recheck before transport, including redirects.
- Unsupported/high-impact mutations stay denied until a separately reviewed tool
  capability and human approval implementation exists.
- Scanner/model confidence never substitutes for human confirmation.

## Local verification resources

Installed Node/pnpm dependencies and Chrome are available. Docker Desktop's selected
socket is absent. No running database was assumed or modified. Database-backed tests
will use an isolated local test database; any unavailable check will be explicitly
recorded with its setup dependency. No Google browser session or GPU was used during
recon, and no benchmark result is inferred from account authorization alone.
